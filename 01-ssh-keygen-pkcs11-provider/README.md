# Windows ssh-keygen loading an unsigned PKCS#11 provider DLL

Proposal: splunk/security_content#4382

**Technique.** Windows OpenSSH `ssh-keygen -D <provider>` passes the provider path to `LoadLibraryW`. The DLL's code runs inside the Microsoft-signed `ssh-keygen.exe`, and no child process is created.

**Lab.** Host A in [LAB.md](../LAB.md) (Windows 11 x64), native OpenSSH 9.5.6.2 (`C:\Windows\System32\OpenSSH`), Sysmon 15.22. The provider is a benign marker DLL (`lab/provider-marker.c`): its `C_GetFunctionList` export only writes a marker file, so the test shows that the code really ran. The bypass cases use copies of the same marker named `evil.dll` and `signed.dll`; `signed.dll` carries a self-signed Authenticode signature.

**Dataset.** `data/windows-events.log`: 488 events (EID 1: 15, EID 7: 473) from 15 `ssh-keygen.exe` runs. sha256 `3c262054fb9e98794744cff6036981220fe9dd902e05ae3c3fd8971c4c1bb134`.

## What the data shows
- Sysmon EID 7 logs the same canonical `ImageLoaded` path whatever form the argument took (relative, no extension, forward slashes, `..`, clustered flags). A command-line parser is bypassable; the image load is not.
- The self-signed provider shows `Signed=false`, `SignatureStatus=Unavailable` in Sysmon, so "not validly signed" covers it.
- An earlier draft that compared the `-D` argument with the loaded path matched only 2 of the 9 bypass variants (see `results/lab-results.md`).
- No existing ESCU or Sigma analytic references `ssh-keygen` or PKCS#11. The existing EID 7 analytics need Temp/UNC paths or known DLL names.

## Limits
- Unsigned providers that are authorized and live outside Program Files will match; tune them with the filter macro.
- A provider signed with a trusted certificate is not detected.
- Renamed copies of ssh-keygen are not covered (Windows OpenSSH binaries have no OriginalFileName).
- `ssh.exe` / `scp.exe` PKCS11Provider and `ssh-sk-helper.exe` are out of scope.

## Reproduce
- **Replay the dataset in any Splunk with ESCU and the Sysmon / Windows TA:** load `data/windows-events.log` with sourcetype `XmlWinEventLog` and source `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational`, then run the YAML searches with the filter macro removed. `tools/replay.py` does exactly this and writes `results/splunk-replay.md`.
- **Regenerate the dataset:** run the capture script in `lab/` on the machine described in [LAB.md](../LAB.md).
